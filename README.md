# ADT Linear Organization: Lazy Collections & Algorithms

Расширение библиотеки ADTLinearOrganization: реализованы механизмы ленивых вычислений (Lazy Evaluation), мемоизации, работа с бесконечными множествами, полиморфные потоки данных и высокопроизводительный алгоритм поиска подстрок.

## Архитектура и основная логика

### 1. Ленивая последовательность (`LazySequence<T>`)
Неизменяемая (immutable) структура данных, элементы которой вычисляются только в момент реального обращения к ним.
*   **Мемоизация (кэширование):** единожды вычисленный элемент сохраняется во внутреннем кэше. Повторное обращение к нему происходит за время $O(1)$.
*   **Иммутабельность и ленивые мутации:** реализованы операции `Append`, `InsertAt`, `RemoveAt` (а также `RemoveFirst`/`RemoveLast`) и извлечение подпоследовательностей. Любая мутация не изменяет оригинальную коллекцию, а возвращает новую `LazySequence`. Под капотом создается независимый снимок (Snapshot) состояния, поверх которого накладывается декоратор с отложенными операциями.

### 2. Генераторы и Скользящее Окно (`Generator<T>`)
Основа ленивых вычислений. Автономные сущности, не знающие о своих владельцах.
* **RuleGenerator:** генерирует элементы по заданному рекуррентному правилу, используя паттерн *Скользящего окна (Sliding Window)*. Идеально подходит для бесконечных математических последовательностей (например, чисел Фибоначчи), так как хранит в памяти только минимально необходимый контекст.
* **SequenceGenerator (наблюдатель):** легковесный адаптер. Позволяет генератору читать элементы из любой внешней коллекции за $O(1)$, не управляя ее памятью (передается по `const`-указателю).
* **SnapshotGenerator (снимок):** специализированный генератор для мутаций. Берет на себя владение склонированной коллекцией (снимком состояния) и автоматически освобождает память при уничтожении согласно парадигме *RAII*. Разделение логики со `SequenceGenerator` гарантирует соблюдение *Принципа единственной ответственности (SRP)*.
* **EmptyGenerator:** реализация паттерна *Нулевой объект (Null Object)*. Используется как безопасная заглушка для пустых последовательностей или коллекций, уже загруженных в кэш. Избавляет ядро от необходимости делать проверки на `nullptr`.
* **ConcatGenerator**: объединяет несколько генераторов в единую цепь. Автоматически «сплющивает» (flatten) внутреннюю структуру при объединении, предотвращая квадратичную сложность обхода $O(N^2)$ и переполнение стека при многократных каскадных склейках.
* **ModifiedGenerator (декоратор):** позволяет наслаивать отложенные мутации поверх базового потока генерации. Использует алгоритм внутреннего "заглядывания вперед" (*Lookahead / Буферизация*), что позволяет безошибочно пропускать удаленные элементы и сохранять строгую константность метода `HasNext()`.

### 3. Трансфинитные числа (`Ordinal`)
Поскольку ленивые коллекции могут быть бесконечными, обычный `int GetLength()` не подходит. Реализована структура `Ordinal`, поддерживающая строгую ординальную арифметику (формы $\omega \cdot c + v$). Это позволяет математически корректно пересчитывать индексы при конкатенации бесконечных последовательностей (где предшествующие константы поглощаются бесконечностью, а бесконечности могут складываться: $\omega + \omega = \omega \cdot 2$).

### 4. Полиморфные Потоки I/O (`InputStream<T>` и `OutputStream<T>`)
Единые интерфейсы для абстрагирования алгоритмов от физического источника и приемника данных.
*   `SequenceInputStream`: предоставляет интерфейс последовательного доступа к элементам ленивых или обычных коллекций в оперативной памяти. Доступ оптимизирован до $O(1)$ за счет использования интерфейса `IEnumerator`. Применен паттерн *Защитное программирование (Defensive Programming)*: если исходная коллекция не поддерживает итераторы, поток безопасно предоставляет доступ через fallback-механизм `Get(index)`.
*   `FileInputStream` / `FileOutputStream`: реализации потоков для посимвольного обмена данными с файловой системой.
*   `SequenceOutputStream`: канал последовательного вывода данных в коллекции `Sequence`. Реализует семантику передачи владения *(Ownership)*: поток может направлять данные во внешние коллекции или аккумулировать их в новой памяти, безопасно отдавая готовый результат через `ReleaseSequence()`.

## Алгоритм Ахо-Корасик (Aho-Corasick)
Для поиска подстрок реализован алгоритм Ахо-Корасик, позволяющий искать множество паттернов одновременно за один проход за $O(N)$.

**Реализация**
* **Универсальность символьных типов:** алгоритм реализован в виде шаблонного класса `AhoCorasick<CharT = char>`, что позволяет использовать его как для стандартных строк (`std::string`), так и для широких символов (например, `std::wstring` с типом `wchar_t`).
* **Потоковый анализ данных:** метод `ProcessStream` принимает на вход полиморфный указатель на `InputStream<CharT>`, что позволяет сканировать как коллекции в оперативной памяти (через `SequenceInputStream`), так и файлы на диске (через `FileInputStream`) без предварительной загрузки всего объема данных в RAM.
* **Управление памятью:** для обхода дерева в ширину (BFS) при построении суффиксных ссылок реализована очередь `NodeQueue` на базе `DynamicArray`.
* **Защита от Heap Corruption:** так как суффиксные ссылки (`fail transitions`) превращают Trie (префиксное дерево, бор-дерево) в циклический конечный автомат (DFA), стандартное рекурсивное удаление узлов в деструкторе приводит к ошибке двойного освобождения памяти (`Double Free`). Для решения этой проблемы в классе `Trie` реализован tracker-массив `DynamicArray<Node*> tracker`. Каждый узел регистрируется в трекере в момент выделения памяти на куче. Деструктор дерева последовательно удаляет узлы из этого плоского массива, полностью игнорируя циклические переходы графа автомата, что гарантирует безопасное удаление каждого узла ровно один раз за время $O(V)$.
* **Оптимизация локальности данных:** списки индексов совпавших паттернов внутри структуры узла бор-дерева (`Node`) хранятся по значению (на базе `DynamicArray` внутри структуры узла), что снижает количество мелких аллокаций в куче и уменьшает фрагментацию памяти.

## Структура проекта

*   `app/` — исходный код консольного приложения (точка входа `main.cpp` и `UI.cpp`).
*   `src/` — реализация базовой логики, алгоритмов и структур данных.
*   `tests/` — модульные тесты с использованием Google Test.
*   `CMakeLists.txt` — конфигурация сборки.

## Руководство по сборке

### Требования
*   **Компилятор:** Поддерживающий стандарт C++20 (GCC, Clang, MSVC).
*   **Система сборки:** CMake версии **3.14** или выше.
*   Подключение к интернету (для автоматического скачивания базового репозитория и Google Test при первой сборке).

### Сборка через консоль (Linux / macOS / Windows Git Bash)
1. Клонируйте репозиторий и перейдите в папку проекта:
   ```bash
   git clone https://github.com/VenEraBle842/ADTLinOrgLazyEvaluation.git
   cd ADTLinOrgLazyEvaluation
   ```
2. Создайте директорию для сборки и запустите CMake:
   ```bash
   mkdir build && cd build
   cmake ..
   ```
3. Соберите проект:
   ```bash
   cmake --build .
   ```

### Сборка через CLion / Visual Studio
Просто откройте папку проекта в вашей IDE. CMake профиль настроится автоматически, а все зависимости будут загружены в фоновом режиме. У Вас появятся два таргета для запуска: `App` (основная программа) и `Tests` (тесты).

## Запуск программы

После успешной сборки в папке `build` (или `cmake-build-debug` в CLion) появятся исполняемые файлы.

### Запуск основного приложения
```bash
./App    # На Linux/macOS
App.exe  # На Windows
```

Приложение предоставляет интерактивное консольное меню со следующими опциями:
1. **Manual Mode:** позволяет ввести произвольный текст и паттерн для поиска (поддерживаются пробелы). Введенный текст записывается в поток `SequenceOutputStream`, после чего извлекается в виде последовательности и считывается через `SequenceInputStream`. Алгоритм Ахо-Корасик обрабатывает полученный поток данных и выводит частоту вхождения заданного паттерна.
2. **Auto Mode:** в данном режиме программа автоматически создает файл `load_test.txt` объемом в 1 000 000 символов (100 000 повторений строки `"ababacabad"`) с помощью `FileOutputStream`. После этого запускается посимвольное чтение файла через `FileInputStream` и поиск вхождений четырех паттернов (`"abacaba"`, `"bad"`, `"caba"`, `"xyz"`) за один проход алгоритма Ахо-Корасик. Результаты поиска выводятся на экран.
3. **Exit:** завершение работы программы.

### Запуск тестов
Проект покрыт модульными тестами с помощью фреймворка Google Test. Для запуска выполните:
```bash
./Tests    # На Linux/macOS
Tests.exe  # На Windows
```
Либо используйте встроенную утилиту CMake:
```bash
ctest --output-on-failure
```
Тесты проверяют
* **математику трансфинитных чисел (`test_Ordinal.cpp`):** проверяется корректность выполнения арифметических операций (сложение, вычитание, сравнение) над ординалами вида $\omega \cdot c + v$, которые используются для индексации бесконечных последовательностей.
* **ленивые вычисления и кэширование (`test_LazySequence.cpp`):** тестируется ленивый характер генерации элементов, корректность работы механизма мемоизации (сохранение вычисленных значений в кэше) и поведение конструкторов при передаче бесконечных коллекций.
* **иммутабельность коллекций (`test_LazySequence.cpp`):** контролируется строгое сохранение исходного состояния объектов после применения цепочки отложенных мутаций (`Insert`, `Remove`, `Append` и извлечение подпоследовательностей).
* **итераторы (`test_LazySequence.cpp`):** проверяется работоспособность итераторов и их применимость в стандартных циклах `range-based for`.
* **полиморфизм потоков (`test_Stream.cpp`):** тестируется корректность работы различных реализаций потоков (`FileInputStream`, `SequenceInputStream`, `FileOutputStream`, `SequenceOutputStream`), а также надежность резервного fallback-механизма чтения при работе с коллекциями, не поддерживающими стандартные итераторы.
* **поиск подстрок и управление памятью (`test_Trie.cpp`, `test_SubstringFrequency.cpp`):** проверяется правильность построения суффиксных/финальных ссылок в префиксном дереве, корректность подсчета частот алгоритмом Ахо-Корасик, а также отсутствие утечек памяти (безопасная очистка циклического автомата через `DynamicArray<Node*> tracker`).
