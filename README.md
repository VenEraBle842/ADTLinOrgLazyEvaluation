# ADT Linear Organization: Lazy Collections & Algorithms

Расширение библиотеки ADTLinearOrganization: реализованы механизмы ленивых вычислений (Lazy Evaluation), мемоизации, работа с бесконечными множествами, полиморфные потоки данных и высокопроизводительный алгоритм поиска подстрок.

## Архитектура и основная логика

### 1. Ленивая последовательность (`LazySequence<T>`)
Неизменяемая (immutable) структура данных, элементы которой вычисляются только в момент реального обращения к ним.
*   **Мемоизация (кэширование):** единожды вычисленный элемент сохраняется во внутреннем кэше. Повторное обращение к нему происходит за время $O(1)$.
*   **Иммутабельность:** любые операции мутации (добавление, вставка) не изменяют оригинальную коллекцию, а возвращают новую `LazySequence`, накладывая декораторы на базовый генератор.

### 2. Генераторы и Скользящее Окно (`Generator<T>`)
Основа ленивых вычислений. Автономные сущности, не знающие о своих владельцах.
*   **RuleGenerator:** генерирует элементы по заданному рекуррентному правилу, используя паттерн "скользящего окна" (например, для чисел Фибоначчи).
*   **ModifiedGenerator (декоратор):** позволяет внедрять отложенные мутации в поток генерации без фактического изменения уже сгенерированных элементов.

### 3. Трансфинитные числа (`Cardinal`)
Поскольку ленивые коллекции могут быть бесконечными, обычный `int GetLength()` не подходит.
Реализована структура `Cardinal`, поддерживающая арифметику и сравнение с бесконечностью. Попытка запросить длину у бесконечного списка безопасно прерывается логическим исключением, защищая программу от зависаний (Infinite Loop).

### 4. Полиморфные Потоки (`Stream<T>`)
Единый интерфейс `ReadOnlyStream` для чтения данных откуда угодно.
*   `SequenceStream`: чтение данных из ленивых или обычных коллекций в оперативной памяти.
*   `FileCharStream`: побайтовое чтение огромных файлов напрямую с жесткого диска.

## Алгоритм Ахо-Корасик (Aho-Corasick)
Для поиска подстрок реализован алгоритм Ахо-Корасик, позволяющий искать **множество паттернов одновременно за один проход ($O(N)$)**.

**Реализация:**
*   Принимает на вход полиморфный поток `ReadOnlyStream<char>`, что позволяет сканировать как списки в памяти, так и гигабайтные файлы без загрузки их в RAM.
*   **Управление памятью:** написан кольцевой буфер `NodeQueue`.
*   **Защита от Heap Corruption:** Так как суффиксные ссылки (`fail transitions`) превращают Trie (префиксное дерево) в зацикленный конечный автомат (DFA), обычные деструкторы вызывают рекурсивное двойное удаление (Double Free). Разработан специальный менеджер `ArrayList<Node*> tracker`, который гарантирует безопасное удаление каждого узла ровно 1 раз в плоском цикле за счет отвязки логики очистки памяти от топологии графа: каждый узел регистрируется в линейном массиве строго в момент выделения памяти на куче, поэтому деструктор, проходя по массиву, полностью игнорирует сложые (в т.ч. зацикленные) суффиксные переходы внутри самого автомата.

## Структура проекта

*   `app/` — исходный код консольного приложения (точка входа `main.cpp` и `UI.cpp`).
*   `src/` — реализация базовой логики, алгоритмов и структур данных.
*   `tests/` — модульные тесты с использованием Google Test.
*   `CMakeLists.txt` — конфигурация сборки.

## Руководство по сборке

### Требования
*   **Компилятор:** Поддерживающий стандарт C++20 (GCC, Clang, MSVC).
*   **Система сборки:** CMake версии **3.14** или выше.
*   Подключение к интернету (для автоматического скачивания базового репозитория и Google Test при первой сборке).

### Сборка через консоль (Linux / macOS / Windows Git Bash)
1. Клонируйте репозиторий и перейдите в папку проекта:
   ```bash
   git clone https://github.com/VenEraBle842/ADTLinOrgLazyEvaluation.git
   cd ADTLinOrgLazyEvaluation
   ```
2. Создайте директорию для сборки и запустите CMake:
   ```bash
   mkdir build && cd build
   cmake ..
   ```
3. Соберите проект:
   ```bash
   cmake --build .
   ```

### Сборка через CLion / Visual Studio
Просто откройте папку проекта в вашей IDE. CMake профиль настроится автоматически, а все зависимости будут загружены в фоновом режиме. У вас появится два таргета для запуска: `App` (основная программа) и `Tests` (тесты).

## Запуск программы

После сборки в папке `build` (или `cmake-build-debug` в CLion) появятся исполняемые файлы.

### Запуск основного приложения
```bash
./App    # На Linux/macOS
App.exe  # На Windows
```

**Доступные режимы (UI):**
1.  **Manual Mode:** позволяет ввести произвольную строку с клавиатуры и найти в ней нужную подстроку с помощью Ахо-Корасик.
2.  **Auto Mode:** нагрузочное тестирование. Программа сама сгенерирует текстовый файл на 1 000 000 символов и просканирует его в потоковом режиме, доказав работу за константное по памяти время и $O(N)$ по скорости.

### Запуск тестов
Проект покрыт модульными тестами с помощью фреймворка Google Test. Для запуска выполните:
```bash
./Tests    # На Linux/macOS
Tests.exe  # На Windows
```
Либо используйте встроенную утилиту CMake:
```bash
ctest --output-on-failure
```
Тесты проверяют:
* корректную математику трансфинитных чисел.
* ленивость генерации и мемоизацию (на примере чисел Фибоначчи).
* полиморфизм потоков (Sequence Stream).
* отсутствие утечек и корректный подсчет частот в алгоритме Ахо-Корасик.
